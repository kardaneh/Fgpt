Extractor
=========

This section documents the Fortran metadata extraction pipeline used by
FGPT. The extractor performs static analysis on parsed Fortran modules
and builds the metadata structures required by the isolation,
translation, and JAX conversion workflows.

.. contents:: Contents
   :local:
   :depth: 2

Overview
--------

The extractor operates on the Fortran AST generated by
:class:`~fgpt.core.frontend.processor.Processor` and performs semantic
analysis of subroutines, variables, arrays, loops, and call dependencies.

Its primary responsibilities are:

* Detecting and indexing subroutines and functions.
* Extracting dummy arguments and actual argument mappings.
* Building inter-procedural call graphs.
* Resolving external dependencies across modules.
* Classifying variables as local, global, dummy, scalar, or array.
* Inferring variable usage (``IN``, ``OUT``, ``INOUT``).
* Extracting array shape information (delegated to
  :mod:`~fgpt.core.analysis.shaper`).
* Identifying vectorized loops.
* Providing metadata required by
  :class:`~fgpt.core.transpiler.transformer.Transformer` and
  :class:`~fgpt.isolator.Isolator`.

Extractor Class
---------------

:class:`~fgpt.core.frontend.extractor.Extractor` is the central metadata
analysis engine used by FGPT. It performs a static analysis of the
parsed Fortran AST and builds the metadata structures required by the
isolation, translation, and JAX conversion workflows.

Its responsibilities include:

* Identifying subroutines and functions present in a source file.
* Resolving inter-procedural dependencies and call relationships.
* Extracting dummy arguments and call-site argument mappings.
* Collecting variable declarations and usage information.
* Inferring argument intents (``IN``, ``OUT``, and ``INOUT``).
* Determining array dimensions and shape dependencies, via
  :mod:`~fgpt.core.analysis.shaper`.
* Identifying vectorized loops and iteration patterns.
* Organizing extracted metadata for downstream processing.

Subroutine and Dependency Analysis
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The extractor constructs a call graph describing relationships between
subroutines and functions. When a routine references external
procedures, the extractor calls
:class:`~fgpt.core.frontend.navigator.Navigator` to search dependent
modules and locate their definitions, establishing the required
dependencies.

This information is later used by :class:`~fgpt.isolator.Isolator` to
construct standalone subroutine environments and by
:class:`~fgpt.core.transpiler.transformer.Transformer` to generate complete
Python implementations.

Variable and Intent Analysis
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The extractor analyzes variable declarations and usage patterns to
classify variables as scalars, arrays, local variables, globals, or
dummy arguments.

When explicit Fortran ``INTENT`` declarations are unavailable, usage
patterns are examined to infer whether a variable behaves as an
``IN``, ``OUT``, or ``INOUT`` argument. This metadata is used during
translation to construct appropriate Python interfaces and data flows.

Array Metadata Extraction
~~~~~~~~~~~~~~~~~~~~~~~~~

Array declarations are inspected to determine dimensionality, shape
dependencies, and indexing information. This work is carried out by the
dedicated :mod:`~fgpt.core.analysis.shaper` module rather than inline in
the Extractor itself. The resulting metadata is used throughout the
translation pipeline to generate NumPy-compatible array operations and
to preserve the semantics of the original Fortran code.

Loop Analysis
~~~~~~~~~~~~~

The extractor identifies loop structures and records iteration
metadata. Particular attention is given to loops operating over
``kjpindex``, which are commonly used as vectorized iteration spaces in
ORCHIDEE and related scientific models.

These loop descriptions are subsequently used by the translation pipeline
and, downstream, by the JAX-conversion backend's own loop-handling
modules — :mod:`~fgpt.core.backends.jax_converter.loops`,
:mod:`~fgpt.core.backends.jax_converter.dynamic_loops`, and
:mod:`~fgpt.core.backends.jax_converter.vectorization` — for
optimization and vectorization analyses. (See :doc:`jax_conversion` for
how these consume the Extractor's loop metadata.)

Metadata Organization
~~~~~~~~~~~~~~~~~~~~~

All extracted information is consolidated into a collection of
dictionaries describing variables, arrays, loops, dependencies, and
subroutine interfaces. These metadata structures form the primary
communication layer between the extractor and the downstream FGPT
components.

Intent Inference
----------------

The extractor performs intent analysis even when explicit Fortran
``INTENT`` declarations are missing.

For each dummy argument, usage patterns are analyzed to infer whether
the variable behaves as:

* ``IN`` — read-only.
* ``OUT`` — write-only.
* ``INOUT`` — both read and modified.

This information is later used by
:class:`~fgpt.core.transpiler.transformer.Transformer` when constructing
Python classes and function interfaces.


Loop Vectorization Analysis
---------------------------

FGPT identifies vector loops by searching for ``DO`` loops whose upper
bound is ``kjpindex``. These loops are treated as vectorized iteration
spaces and are tracked separately for later optimization and JAX
conversion passes (see :mod:`~fgpt.core.backends.jax_converter.vectorization`).


Dependency Resolution
---------------------

When a subroutine calls another routine that is not defined in the
current module, the extractor delegates to
:class:`~fgpt.core.frontend.navigator.Navigator`, which searches
dependent modules to locate the missing implementation.

This mechanism allows FGPT to automatically construct complete
dependency graphs spanning multiple source files and modules.

   * - Intent Information

     - :class:`~fgpt.core.frontend.extractor.Extractor`
